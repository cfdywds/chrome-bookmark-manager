# 本地同步、发布与回退

## 本地同步

这是个人多设备使用的默认方案，不需要 Chrome Web Store 开发者账号。标签数据由 Chrome 原生书签同步承载，不使用按扩展 ID 隔离且有容量配额的 `chrome.storage.sync`；因此各设备可以加载不同扩展 ID 的本地解压目录。

### 前提

- 使用 Chrome 114 或更高版本，且每台设备登录同一 Google 账号并开启 Chrome 同步。使用自定义同步时，必须开启「书签」同步项。
- 不要将 Chrome 和 Edge 混作同一同步组；本地同步仅支持 Chrome。
- 每台设备都需要手动加载一次本地扩展；Chrome 不会同步或自动更新「加载已解压的扩展程序」。

### 首次配置

1. 选择一台持有现有标签的设备作为起始设备，更新并重新加载到当前版本；建议先导出一份 V4 JSON 备份。
2. 打开设置页，开启「标签原生同步」。扩展会在 Chrome 的「其他书签」下创建 `书签管家同步数据（请勿修改）`，并把当前标签、固定标签池和自定义规则写入该目录。
3. 在每台其他设备打开 `chrome://extensions`，开启开发者模式，选择「加载已解压的扩展程序」，并选择本项目的任意最新版本地副本。无需比较扩展 ID。
4. 等待 Chrome 完成书签同步，打开侧边栏、新标签页或设置页。扩展会自动发现内部目录并读取标签和规则；不要在其他设备重复导入备份。

内部目录会在 Chrome 原生书签管理器和移动端可见，但插件内不会显示或处理它。不要手动修改、移动或删除其中节点；分片写入和头指针用于容忍 Chrome 同步的到达乱序。

书签 URL 仅在原生书签管理器中被修改后，请在插件内重新保存一次该书签的标签，标签才会迁移到新 URL。Chrome 书签事件不提供本机/远端来源，自动发布会在远端书签先于标签分片到达时产生空记录，因此此处优先保证标签不被覆盖。

### 日常更新

1. 在每台设备更新或替换本地扩展目录。
2. 打开 `chrome://extensions`，点击扩展卡片的「重新加载」。无需重新导入备份，也无需重新启用标签原生同步。

若更新新增权限，Chrome 会在重新加载时要求确认。

### 回退

恢复保存的旧扩展目录，并在每台设备重新加载扩展即可。不要为了回退删除内部同步目录，保留它可以在重新升级时继续使用。

### 内部目录恢复

若内部目录被误删，先确认至少一台设备仍保留需要的本地标签，再在该设备关闭并重新开启「标签原生同步」。扩展会重新创建目录并以该设备的当前标签、标签池和规则重建同步数据。不要在没有核对本地数据的设备上执行此操作。

仅支持当前 V4 格式的版本才能导入 V4 备份；早于 V4 的代码不能用于恢复该备份。

### 备份恢复边界

- 导入不会删除当前书签：同一完整 URL 默认合并标签，其余书签新增；确认框可选择保留副本。
- 隐藏状态和回收站记录会合并；固定标签池与自定义标签规则会以备份内容覆盖当前配置。
- 若回收站容量不足，恢复会失败，不会静默删除现有回收站记录。
- 备份与标签原生同步均不包含 API Key、LLM 配置、端点、模型或可选主机权限；标签原生同步也不包含隐藏状态和回收站。

## Chrome Web Store 发布（可选）

本节仅面向维护公开或不公开列出商店版本的维护者。发布到 Chrome Web Store 后，Chrome 可以在符合其同步设置的其他设备自动安装和更新该扩展；本地解压扩展仍必须手动加载和更新。标签数据仍由本节前述的 Chrome 书签同步承载，不依赖扩展 ID。

### 生产发布

1. 在权威设备使用当前版本导出 V4 书签 JSON 备份，并妥善保存，不提交到 Git。
2. 从已审阅的仓库根目录创建 Chrome Web Store 上传 ZIP。上传前确认 ZIP 不包含 API Key、书签备份或 `node_modules`。
3. 将 ZIP 上传到一个 Chrome Web Store 条目，完成审核或发布为不公开列出。
4. 在两个 Chrome 配置文件安装同一个商店条目，并确认两个配置文件登录同一 Google 账号且已开启书签同步。
5. 只在权威配置文件导入备份，启用标签原生同步并确认成功状态；目标配置文件打开侧边栏或新标签页，确认标签、固定标签池和自定义规则到达。
6. 在源配置文件删除一个标签和规则，确认删除也会同步到目标配置文件。
7. 确认目标设备没有收到任何 LLM API Key、端点、模型或 profile。

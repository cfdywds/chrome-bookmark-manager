## 生产发布

Chrome Sync 由扩展 ID 隔离。所有生产设备必须从同一个 Chrome Web Store 条目安装本扩展，首次发布建议使用“不公开列出”状态。发布完成后，在此手册所在的发布记录中写下商店条目 URL 和 `chrome.runtime.id`。

1. 在权威设备使用当前版本导出 V4 书签 JSON 备份，并妥善保存，不提交到 Git。
2. 从已审阅的仓库根目录创建 Chrome Web Store 上传 ZIP。上传前确认 ZIP 不包含开发 manifest、私钥、API Key、书签备份或 `node_modules`。
3. 将 ZIP 上传到一个 Chrome Web Store 条目，完成审核或发布为不公开列出。
4. 在两个 Chrome 配置文件上安装同一个商店条目，打开设置页并记录相同的 `chrome.runtime.id`。
5. 只在权威配置文件导入备份，启用标签云同步并确认成功状态；第二个配置文件打开侧边栏或新标签页，确认标签、固定标签池和自定义规则到达。
6. 在源配置文件删除一个标签和规则，确认删除也会同步到目标配置文件。
7. 确认目标设备没有收到任何 LLM API Key、端点、模型或 profile。

## 解压本地同步

普通解压扩展会在每台设备得到不同 ID，不能同步标签。本项目提供了面向个人使用的一键本地构建：双击仓库根目录的 `prepare-local-sync.cmd`，或执行 `npm run prepare:local-sync`。

脚本会检查 Node.js 版本和运行时资源，首次在权威设备的用户配置目录生成 RSA 私钥，之后始终复用该私钥；它只将公钥写入 `local-sync-build/manifest.json`，并输出预期扩展 ID。私钥不进入仓库或生成目录。权威设备应保留一份加密离线备份，以便系统重装或换机后继续生成相同 ID；绝不提交、上传到共享同步盘或复制到其他使用设备。`local-sync-build/` 已被 Git 忽略。

1. 在权威设备先将原解压扩展更新并重新加载到当前版本，再导出 V4 JSON 备份。
2. 运行一键脚本，在 `chrome://extensions` 开启开发者模式并加载 `local-sync-build`。
3. 在新扩展中导入备份，启用“标签云同步”，记录脚本输出和设置页中一致的扩展 ID。
4. 将整个 `local-sync-build` 目录复制到其他设备；不要复制用户配置目录中的私钥。
5. 所有设备使用 Chrome、登录同一 Google 账户并启用 Chrome 同步；若使用自定义同步，保持扩展程序或设置相关同步项开启。随后在 `chrome://extensions` 加载该目录。同步开关会从权威设备自动到达，扩展 ID 必须完全一致。

Chrome 不允许脚本绕过“加载已解压的扩展程序”的确认，因此每台设备仍需手动选择一次生成目录。这个本地 ID 与 Chrome Web Store 的生产 ID 有意不同，不能用于迁移生产同步数据。

## 回退

1. 在测试配置文件关闭标签云同步。
2. 重新安装原扩展 ID 对应的版本。
3. 仅在支持 V4 的版本中导入发布前导出的 JSON 备份，确认书签标签和规则恢复；早于 V4 的版本不能导入该备份。
4. 不要为了回退删除 Chrome Sync 数据；保留它以便重新升级时恢复。

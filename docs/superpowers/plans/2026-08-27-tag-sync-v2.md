# Tag Sync V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reliably synchronize bookmark labels across devices by mapping them through normalized URLs instead of profile-local bookmark IDs.

**Architecture:** `lib.js` owns the V2 serialization, cloud pull, URL-to-local-ID resolution, and settings status helpers. `background.js` independently projects local tags to the same normalized URL key when a native browser action changes `bmTags`, since it cannot load the UI library. UI surfaces use the shared library for initial pull and user-visible status.

**Tech Stack:** Manifest V3 Chrome extension APIs, classic JavaScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-27-tag-sync-v2-design.md`

## Global Constraints

- Keep the extension build-free and do not add dependencies.
- Preserve all existing local `bmTags` data.
- Never apply a legacy ID-keyed cloud payload on a different device.
- Continue chunking cloud data below the `chrome.storage.sync` per-item limit.
- Use the existing `BM.urlKey()` canonicalization semantics for V2 identity.

```js
function projectTagsForSync(tags, bookmarks) {
  const out = {};
  (bookmarks || []).forEach(bookmark => {
    const key = bookmark && bookmark.url ? urlKey(bookmark.url) : '';
    const values = bookmark && tags && tags[bookmark.id];
    if (!key || !Array.isArray(values)) return;
    out[key] = [...new Set([...(out[key] || []), ...values])].slice(0, MAX_TAGS_PER_BOOKMARK);
  });
  return out;
}
```

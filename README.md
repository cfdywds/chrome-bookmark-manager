# 书签管家 · Bookmark Manager

Chrome / Edge Manifest V3 书签管理扩展。用标签整理书签，清理重复和空文件夹，并提供隐藏、回收站、备份与可选的 AI 打标。

## 功能

- 多标签、标签池、搜索和新标签页书签浏览；归一化同址书签自动保持标签一致。
- 精确重复检测、空文件夹清理、拖拽排序和批量操作。
- 隐藏书签、独立隐藏书签视图、30 天回收站、紧凑 V4 JSON 备份与恢复；恢复默认合并相同 URL，也可保留副本。单书签最多 6 个标签，已有标签优先。
- 可选的 OpenAI 兼容 LLM 打标，以及本地规则建议。
- AI 隐私保护：本地识别登录入口、访问凭据参数与金融/钱包服务；命中项不会发送给 LLM。

## 个人使用

需要 Chrome 或 Microsoft Edge 114 及以上版本。本地加载不需要 Chrome Web Store 开发者账号。

### 单设备本地加载

```bash
git clone https://github.com/cfdywds/chrome-bookmark-manager.git
```

1. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）。
2. 开启「开发者模式」，选择「加载已解压的扩展程序」。
3. 选择本项目根目录，随后在工具栏点击「书签管家」打开侧边栏。

### 个人多设备标签同步

不需要 Chrome Web Store 开发者账号、固定扩展 ID 或私钥。标签数据保存在 Chrome 原生书签的内部目录中，随 Chrome 的「书签」同步到其他设备，因此不同设备加载的本地扩展可以使用不同扩展 ID。

前提：所有设备使用 Chrome、登录同一 Google 账号，并在 Chrome 同步中开启「书签」。不要将 Chrome 和 Edge 混作同一个同步组。

首次配置：

1. 在有现有标签数据的设备先更新并重新加载到当前版本；建议先导出一份 V4 JSON 备份。
2. 打开扩展的设置页，开启「标签原生同步」。扩展会在「其他书签」下创建 `书签管家同步数据（请勿修改）`，并写入当前标签、固定标签池和自定义规则。
3. 在每台其他电脑手动打开 `chrome://extensions/`，开启开发者模式并加载本项目目录（可以是任意复制过去的同版本目录）。Chrome 不会自动安装或更新本地解压扩展。
4. 等待 Chrome 书签同步完成后，打开侧边栏、新标签页或设置页；扩展会自动读取内部目录并应用标签与规则。其他设备不要导入备份，也不需要开启相同的扩展 ID。

内部目录只用于同步，插件的书签列表、搜索、重复清理、空文件夹清理和 V4 备份都会忽略它。不要在 Chrome 书签管理器或移动端修改、移动或删除该目录。若误删，在仍保留当前标签数据的一台设备关闭再重新开启「标签原生同步」即可重建目录。

同步范围是规范化 URL 键的标签、固定标签池和自定义规则；不包含书签标题、API Key、LLM 配置、隐藏状态或回收站。相同 URL 的多个书签共用一组标签；删除标签会作为删除记录同步，避免旧数据复活。完整排查、更新和回退说明见 [本地同步说明](./docs/release/chrome-web-store.md#本地同步)。

若只在 Chrome 书签管理器中修改书签 URL，请随后在插件内重新保存一次该书签的标签。Chrome 不会区分本机编辑和远端书签先到；该限制避免把尚未到达的远端标签误写为空记录。

#### 更新本地扩展

日常更新不需要重新同步标签或导入备份：在每台设备替换为新版项目目录后，打开 `chrome://extensions/` 并点击扩展卡片的「重新加载」。本地解压扩展不会由 Chrome 自动更新；若新版本新增权限，重新加载时会要求确认。需要回退时，恢复旧目录并重新加载即可，内部书签同步数据会保留。

## 备份与恢复

- 备份使用紧凑 V4 JSON，只能由当前版本导出的 V4 文件恢复；迁移前先更新并重新加载原扩展，再导出备份。
- 书签恢复不会删除当前书签：同一完整 URL 默认合并并合并标签，其余书签新增；确认框可选择保留副本。
- 隐藏状态和回收站记录会合并保留；固定标签池和自定义标签规则会以备份内容覆盖当前配置。若需要完全隔离的恢复结果，请在新的 Chrome 配置文件中导入。
- 备份不包含 API Key、LLM 配置、端点、模型或可选主机权限。

## AI 打标

在设置页选择服务商，填写 Base URL、API Key 和模型名后测试连接，再在「标签」页批量打标。支持 OpenAI、DeepSeek、Grok、Groq、Gemini、Ollama 和自定义 OpenAI 兼容服务。批量打标失败时会保留已完成批次，并在当前侧边栏提示中提供“继续打标”，只重试尚未成功写入的书签。也可单独开启“后台静默使用 AI 补充标签”：浏览器新增普通书签时，只有本地规则无法确定用途才会请求 LLM；该开关默认关闭，Chrome 原生批量导入不会触发 LLM。

API Key 仅保存于本机。AI 请求会跳过命中本地隐私保护规则的书签，只发送其余书签的标题、URL 域名和路径，不发送 URL query 或 fragment；首次使用某个服务时，需要授予该 API 域名的网络权限。该规则用于控制 AI 外发，不提供加密、隐藏或浏览器同步隔离。

打标按以下优先级执行，最终标签始终受固定标签池约束：

1. 用户配置的域名关键字规则。
2. 通用平台语义预设，例如代码托管→`代码`、论坛平台→`论坛`、设计协作→`设计/工作`、组网与运维平台→`运维/工具`。默认规则不包含个人主机名或站点专属标签。
3. 用户配置的标题 / URL 路径关键字规则。
4. 通用主题关键词。
5. 手动 AI 打标会保留高置信规则标签并补充至最多 3 个；浏览器后台 AI 仅补充规则未知项。模型失败时保留本地结果。

可在设置页的“自定义打标规则”中按行配置，规则标签必须先存在于固定标签池：

```text
# 域名关键字规则，只匹配 hostname；首个标签也是概览分类
corp=工作,代码

# 标题 / 路径关键字规则
教程=学习,教程
release=资讯
```

匹配不区分大小写。域名规则的首个标签同时决定概览分类，因此不需要再维护另一套域名分组。标题 / 路径规则只读取标题、hostname 和 pathname，不读取 URL query 或 fragment；命中用户规则的浏览器收藏不会再请求后台 AI。旧版域名分组会自动迁入域名规则。

已有书签不会因规则修改而自动覆盖。在“标签”页可使用“应用规则”，选择仅处理未标书签、追加规则标签或覆盖为规则标签；该操作完全在本地执行，不调用 LLM，同一网址的书签会保持相同标签。

## 隐私

- 书签、标签、隐藏状态、回收站和自定义打标规则默认保存在本机。
- 书签由 Chrome 原生同步；启用「标签原生同步」后，规范化 URL 键的标签、固定标签池和自定义标签规则写入内部书签目录，并通过 Chrome 的书签同步到同一 Google 账号的其他设备。同步不包含书签标题或页面内容；不包含 API Key、LLM 配置、端点、模型、隐藏状态或回收站。标签名和规则文字仍可能反映浏览偏好。

完整安全边界与漏洞报告方式见 [SECURITY.md](./SECURITY.md)。

## 开发

扩展没有运行时构建步骤。修改后在扩展管理页点击「重新加载」即可；开发与 CI 使用 Node.js 20。

```bash
npm install
npm test
npm run lint
```

贡献规范见 [CONTRIBUTING.md](./CONTRIBUTING.md)，设计与安全决策见 [DESIGN.md](./DESIGN.md)。

## 维护者发布（可选）

只有维护公开商店版本时才需要此流程。Chrome Web Store 可分发扩展并提供自动更新；标签原生同步仍只依赖同一 Google 账号的书签同步，不依赖扩展 ID。详细流程见 [发布与回退说明](./docs/release/chrome-web-store.md#chrome-web-store-发布可选)。

当前首发版本为 `v1.0.0`。后续版本使用带注释的 `vX.Y.Z` tag；发布前运行：

```bash
npm run check-version
npm run release -- 1.0.1 --push
```

发布脚本会校验版本一致性、单测、ESLint 和远端 tag。推送 tag 后，在 GitHub Releases 页面创建对应 Release。详细变更见 [CHANGELOG.md](./CHANGELOG.md)。
